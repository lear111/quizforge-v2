# 原型显示数据 → 接口来源

依据设计分支 `ecc571b`，不修改其契约。本表覆盖 8 组、16 个尺寸入口的全部**动态显示数据**，桌面与手机来源相同。静态按钮文案、导航、图标、帮助文字和布局尺寸是前端展示常量，不需要后端字段。所有数值都是假数据，不读取线上账户。

**确认程度：**「旧契约」表示沿用旧 Hub/Web 的数据语义，仍需 V2 DTO 核验；「已列明」表示设计已经写出数据/端点；「缺口」表示 API 有相应端点但字段没有明确，括号中的名称只是原型别名。

公共缩写：`B=/api/collections/bank/{id}`，`Q=B/questions/{qid}`。当前集合中的 `id` 是用户实例 ID；包内选择使用 `bank_key`，不混用二者。

| 保存失败的错误文案/请求编号 | 对应写接口的错误响应 | `error.code/message`；500 的 `X-Request-Id` 已列明，本原型未添加额外编号 |
| 默认静态题卡、公式、输入、评分 | `GET Q` 的投影、作答与结果 | 原型使用普通 HTML 占位；实际应由原拓展页面呈现，不增加 Bridge 字段 |

## 布局的本地 UI 状态

大纲 / AI 标签、侧栏开关、拖动尺寸为当前页面 UI 状态，不依赖服务端字段，不读写用户偏好存储。桌面宽度 240～560px，随练习区域可用宽度收窄上限；手机高度 240px 到练习区高度减 100px。

普通用户已移除“有新版本”和手动更新界面。更新后的当前数据仍来自 GET B / GET Q；不显示待更新目标版本，不通过 JS 调用 POST B/update。

## 写入口与边界汇总

页面上的按钮只演示 UI。正式实现对应：

| 交互 | 接口 |
| --- | --- |
| 加入所选/打开已有实例 | `POST /api/packs/{id}/practice {banks:[bank_key…]}` |
| 下载 | `GET /api/packs/{id}/download` / 部分下载 `POST .../download-selection`，先做 `GET .../download-status` |
| 保存/提交/重做/白板 | `POST Q/actions`；`requestId/revision/contentVersion` 沿用原契约 |
| 完成本轮 | `POST B/finish`（沿用旧 summaryVersion 等并发语义，需 DTO 明确） |
| AI 提问/兑换 | `POST Q/tutor` / `POST /api/account/ai/redeem` |
| 上传新版本/删除分享 | `PUT /api/packs/{id}` / `DELETE /api/packs/{id}` |
| 退出 | `POST /api/auth/logout` |

上述端点只写在本说明中，**任何 HTML/JS 都不请求这些接口**。未实现用户管理、文件上传、服务重试、评分、更新/合并、冻结历史或 AI 业务逻辑。
