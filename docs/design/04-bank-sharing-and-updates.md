# 题库共享与版本更新

> **文档版本：** v1.0
> **日期：** 2026-11-04
> **依据：** [需求 FR-10、FR-11](../requirements/01-requirements.md)，[数据库设计](01-database.md)，[rule-runner 协议](03-rule-runner-protocol.md)

本文说明三件事：题库内容如何在用户之间共享；作者增、删、改题库后，用户的题库如何变化；自动更新的具体算法与并发处理。

---

## 1. 概念回顾

```text
题库包（catalog_pack）            作者上传的一个“组”，包含多本题库
 └─ 版本（catalog_pack_revision）  作者每次更新产生一个新版本，需审核
     └─ 包内题库（catalog_pack_bank） 某版本中的一本题库 → 指向一份共享内容（content_bank）

用户的题库实例（practice_collection）  指向某个包内题库的某个版本的内容
 └─ 作答、草稿、历史、考试             用户私有
```

- **共享内容不可变**：每个版本的每本题库对应一份 `content_bank`；内容相同则复用同一份（`content_sha256` 唯一）。
- **包内题库的身份（2026-10-29 修订）**：`bank_uuid` = `bank.json` 中必填的 UUID（设计 06 第 4 节）。新旧版本中 UUID 相同的题库视为“同一本题库的不同版本”，作者修改文件夹名不影响对应关系。下文及第 4 节中的 `bank_key` 一律改为 `bank_uuid CHAR(36)`。
- **不同题库包之间的 UUID（2026-11-01 决定）：** UUID 只在同一个题库包内用于对应新旧版本（主键含 `pack_id`），不同包之间相同不影响正确性。第一版**不做自动检测**：发布者误把更新传成新包、原样上传他人题库等情况，由管理员在审核时人工判断。

## 2. 作者操作与用户效果

| 作者操作 | 平台处理 | 已加入的用户 |
| --- | --- | --- |
| **增**：上传新的题库包 | 新建 `catalog_pack` 与第 1 个版本，审核通过后公开 | 无影响 |
| **改**：上传新版本 | 新建版本，审核中时**继续公开上一个已审核版本** | 新版本审核通过后自动更新（第 3 节） |
| 新版本中去掉某本题库 | 该 `bank_key` 在新版本中不存在 | 保留该题库，停在最后一个版本，标记“作者已移除，不再更新” |
| 新版本中题库改名 | 视为删除旧题库 + 新增一本 | 旧题库同上保留；新题库需要用户自己加入 |
| **删**：删除整个题库包 | 题库包下架，不再出现在广场中 | 全部保留，标记“作者已移除，不再更新” |
| **查**：查看题库包信息 | 只读 | 无影响 |

> **第一版范围（2026-11-01，需求 FR-10 v1.13）：** 发布者只有两种写操作——上传整包新版本、删除整个题库包。表中“新版本中去掉某本题库”“新增题库”都通过上传整包新版本完成，不提供按本添加、替换或移除的按钮。

> 与旧 Hub 的差异：旧 Hub 中作者编辑后，整个题库包暂停公开，直到重新审核通过。V2 改为新版本审核期间继续提供上一个已审核版本，用户不会因为作者正在修改而看不到题库。

**共享内容不会因作者删除而丢失：** 内容只有在**没有任何用户实例、历史记录、考试和题库包版本引用**时，才会被后台垃圾回收删除（ADR-007）。

## 3. 自动更新规则（2026-10-29 简化）

**原则：只在一本题库“没有进行中的作答”时切换版本，切换时整本替换，不做逐题合并。** 作答与题目永远来自同一个版本，不会出现“新题配旧作答”。代价是用户正在做的这一轮，要等到下一轮才用上新版本；题库更新不频繁，这个代价可以接受（需求 FR-10 v1.6）。

### 3.1 何时切换

“有进行中的作答”指：该题库的普通练习存档中存在状态为 `draft` 或 `submitted` 的作答行，或者该题库有进行中 / 评分中的考试。

| 用户题库的状态 | 处理 |
| --- | --- |
| 没有进行中的作答（从没开始，或“再练一次”后尚未作答） | 下次打开时**直接切换**到最新的已审核版本 |
| 有进行中的作答（含已点“完成”、但还没点“再练一次”） | **不切换**，继续使用当前版本；概览中提示“有新版本，再练一次时使用” |
| 用户点击“再练一次” | 在同一个事务中：清空作答（与原有“再练一次”相同）→ 切换到最新的已审核版本 |

不提供“立即更新”。考试引用开考时的 `bank_id`，本身就是冻结的；新开的考试使用题库实例当前的版本。

### 3.2 何时检查

**懒更新：不在作者发布时批量修改所有用户的数据，而是在用户打开题库时检查。**

- 用户请求题库概览（`GET /api/collections/bank/{id}`）或“再练一次”时，比较 `practice_collection.source_revision` 与该题库包最新的**已审核**版本。
- 可以切换 → 在本次请求中完成切换，再返回新版本的概览。
- 暂不能切换 → 返回当前版本概览，附带 `update:{status:"pending", revision}`。

为什么不在发布时批量更新：

1. 批量修改几百个用户的数据是一个耗时的大事务，容易和用户正在进行的保存冲突；
2. 很多用户可能很久都不会再打开这本题库，提前更新没有意义；
3. 懒更新让每个用户的切换都是一个独立的小事务，失败只影响这一个人，下次打开时重试即可。

### 3.3 通知

版本审核通过时，系统自动发送一条题库更新通知（需求 FR-12，`notification.kind = 'bank_update'`，`pack_id` 关联该题库包），内容包含作者填写的更新说明。拥有该题库的用户在通知列表中看到它，不为每个用户复制。

### 3.4 事务与并发

切换只修改题库实例指向的内容，不碰作答行（切换时本来就没有进行中的作答）：

```text
BEGIN
  SELECT ... FROM practice_collection WHERE id = ? AND user_id = ? FOR UPDATE
      —— 锁住题库实例：防止同一用户两个页面同时触发切换
  再次确认：source_revision 仍是旧值（已被另一个请求切换则直接结束）
  SELECT ... FROM practice_context WHERE collection_id = ? AND kind = 'practice' FOR UPDATE
      —— 锁住普通练习存档：与保存、提交、完成本轮互斥（加锁顺序：collection → context → state）
  再次确认没有进行中的作答（第 3.1 节的条件），否则结束
  practice_collection.bank_id = 新内容，source_revision = 新版本，update_status = 'current'
  practice_context.progress_version + 1
COMMIT
```

- 切换不需要调用 rule-runner：新版本每题的满分已在导入时算好。
- 切换与第一次保存并发时：两者都要锁住普通练习存档，后者等待前者提交后再执行；如果切换先完成，前端拿着旧版本读到的题目保存，会因题目内容版本不一致被拒绝并刷新。
- 冻结历史永不改变：`practice_round` 与 `practice_round_question` 保存当时的快照，并引用当时的拓展包摘要。
- 分组名、用户自定义的标题保留，不被作者的新标题覆盖。

### 3.5 实现说明（题库广场 3/4，2026-11-04）

- **入口**：`PracticeUpdates`（practice 模块）。打开题库概览时 `open()`；“再练一次”的归档任务在清空作答的同一事务中 `afterRestart()`；练习空间题库列表 `list()` 只读、批量查询。广场的已审核版本通过 `PublishedVersions` 端口读取，由 catalog 模块实现（practice 不读写 catalog 表）。
- **只看已审核版本**：`catalog_pack.approved_revision`；新版本审核中、包不公开或已删除都不切换。
- **按 `source_bank_uuid` 对应**：新版本中有这个 UUID → 切换到它的 `bank_id`；没有 → `update_status = 'removed'`（作者已移除，此后不再更新，即使以后的版本又出现这个 UUID）。整个包删除 → 读取时显示 `deleted`（作者已删除），不写库。两种情况练习照常可用。
- **新版本中这本题库内容未变**（同一份共享内容）：直接推进 `source_revision`，不受进行中的作答影响，也不提示“有新版本”。
- **“有进行中的作答”**（第 3.1 节）在实现中为：普通练习存档中有 `draft` / `submitted` 的作答；存档不处于 `active`（已完成未再练一次、正在完成、正在归档）或有后台任务；白板上有内容；该题库有 `in_progress` / `grading` 的考试。白板一项是对第 3.1 节的补充：只画了白板没有作答时切换会让白板对应到新题目，所以同样等到“再练一次”。
- **事务**：先不加锁判断；确有可切换的新版本时，开启事务按 **context（`FOR UPDATE`）→ collection（`FOR UPDATE`）** 的顺序加锁，再次确认版本未变、没有进行中的作答后切换（`bank_id`、`source_revision`、`source.revision`，`progress_version + 1`）；标题与分组不变。存档不存在（从未打开）时只锁实例，不加锁读不存在的行。**与第 3.4 节写的 collection → context 顺序相反（待作者确认）**：已有的保存、提交、完成练习都先锁存档，草稿保存再在同一条 SQL 中读取题库实例确认题目版本（`INSERT … SELECT` / `UPDATE … WHERE EXISTS` 对读取的行加共享锁），按 3.4 的顺序会与第一次保存形成死锁（并发测试中复现过）；context 在前也与 CLAUDE.md 的 `practice_context → practice_question_state → practice_round` 一致。
- **题目版本校验**：草稿的插入与更新（提交也先经过草稿保存）都在同一条 SQL 中确认作答所用的 `content_sha256` 属于存档当前指向的题库（考试存档按开考时冻结的 `exam_exam.bank_id`），主键查找。切换之后拿着旧版本题目的保存影响 0 行，返回 409 要求刷新；因此切换与第一次保存任意交错时，作答与题目都来自同一个版本。浏览器判分上报、人工评分、重做、完成练习都要求已有作答，有作答时不会切换。
- **再练一次**：归档任务最后一个事务锁住存档、清空作答后，再锁题库实例并切换；有进行中或评分中的考试时不切换，下次打开时再切换。冻结的历史（`practice_round_question`）不变。

### 3.6 更新通知（实现）

- 公开题库包第 2 版及以后的版本审核通过时（管理员审核，或管理员上传自动通过），系统发送一条通知：`notification.audience = 'bank'`、`target_id = 题库包 ID`、`source = 'system'`，正文为作者填写的更新说明。只存一份，读取时按“用户是否拥有该包的未删除实例”（`practice_collection.source_pack_id`）筛选。
- 按题库包而不是按 `bank_uuid` 筛选：不同包之间 UUID 可能相同（第 1 节），按 UUID 会把通知发给其他包的用户；私人导入的实例不接收。
- 公开包的新版本**必须填写更新说明**（发布页面与服务器都检查）。
- 收藏（`catalog_favorite.seen_revision`）：记录收藏者最后确认过的已审核版本；“我的题库”的收藏分区在有新版本时显示版本号与更新说明，点“知道了”后不再提示。

## 4. 数据库变更

```sql
CREATE TABLE catalog_pack_bank (                   -- 某个版本中的一本题库
  pack_id    CHAR(36)      NOT NULL,
  revision   INT           NOT NULL,
  bank_uuid  CHAR(36)      NOT NULL,               -- bank.json 中的 UUID：题库身份（设计 06 第 4 节）
  bank_id    CHAR(36)      NOT NULL,               -- 共享内容 content_bank.id
  title      VARCHAR(300)  NOT NULL,
  PRIMARY KEY (pack_id, revision, bank_uuid),
  KEY idx_pack_bank_content (bank_id)
);
```

`practice_collection` 的来源与更新状态字段（V1 中的 `source_bank_key` 在实现题库广场时改为 `source_bank_uuid CHAR(36)`）：

```sql
  source_pack_id    CHAR(36)  NULL,                -- 指向公开包或私人包（第 6 节）
  source_bank_uuid  CHAR(36)  NULL,
  source_revision   INT       NULL,                -- 当前使用的版本
  update_status     ENUM('current','pending','removed') NOT NULL DEFAULT 'current',
      -- pending：有新版本，等待没有进行中的作答时切换；removed：作者已移除，不再更新
  KEY idx_collection_source (source_pack_id, source_bank_uuid)
```

`catalog_pack` 增加 `approved_revision`（最新的已审核版本），审核通过时更新；用户打开题库时与 `source_revision` 比较。

## 5. 接口变更

| 接口 | 变更 |
| --- | --- |
| `GET /api/collections/bank/{id}` | 响应增加 `update:{status, revision?, removed?}`；可以切换时，在返回前完成切换 |
| `POST .../restart`（再练一次） | 若有更新的已审核版本，清空作答后切换到新版本 |
| `POST /api/packs/{id}/practice` | 加入“我的题库” `{banks:[bank_uuid…]}`，按本选择；同一用户重复加入同一本时，打开已有的实例 |

## 6. 我的题库与私人题库（需求 FR-11）

### 6.0b 上传与后台排队校验（2026-11-02，需求 FR-11 v1.16）

```text
上传 ──► 只接收并保存原始文件（按文件大小预留配额）──► “我的题库”立即出现：待审核
                                                         │ 后台队列，按上传先后
                                                         ▼
                                          解压与安全检查、规则校验（低优先级名额）
                                            ├─ 失败 ──────────────► 未通过（原因）
                                            ├─ 含未批准拓展 ──────► 待审核（等管理员）
                                            └─ 拓展全部已批准 ────► 可用（私人）/ 待审核（发布到广场，等版本审核）
```

- **用户只看到三种状态**：待审核、可用、未通过（附原因）。排队中、校验中都显示为“待审核”。
- **上传请求只做**：登录、每日次数、`Content-Length` 与剩余配额检查 → 流式保存原文件 → 建立记录 → 立即返回。不解压、不运行规则。
- **队列**：数据库任务表即队列（与完成练习的后台任务相同的租约、重试与栅栏机制），按创建时间先后领取；全站并发固定（默认 1，可配置）；规则调用只使用后台名额，不占前台。进程重启后从队列继续。
- **防御恶意上传**：单个题库包大小上限（沿用 128 MiB，可配置）；每用户每日上传次数上限（默认 20，可配置；界面不预先显示，超过时返回“请稍后再试”）；个人存储配额在上传时按原始文件大小预留，校验失败的条目删除后释放。
- **管理员上传**：同样排队；校验通过后按“管理员上传免审核”规则自动批准。
- **与 ADR-011 的关系**：私人上传不再在浏览器中校验，改为本节的服务器后台队列；ADR-011 的“判分在浏览器中执行”不变。

**细节（作者 2026-11-02 确认）：**

| 项 | 规则 |
| --- | --- |
| 用户可见状态 | **待审核**（排队、校验中、等待管理员）；**已审核**——结果为“通过”（可用）或“未通过”（附原因） |
| 重复上传相同文件 | 允许，每次都是独立条目，用户自己负责删除 |
| 状态通知 | 审核结果（通过 / 未通过及原因）以站内通知发给上传者 |
| 未通过的条目 | **保留**提交时的信息（广场信息、文件名、拒绝原因与时间），继续计入配额，直到用户删除；用户可以**在该条目中重新上传**题库包重试：私人题库包产生新的版本，发布到广场的题库包按 FR-10 上传整包新版本，重新进入待审核；条目中保留每次提交的结果记录 |
| 内容问题与服务器问题 | 文件本身有问题（格式、结构、拓展被拒绝）→ 未通过并给出原因；rule-runner 暂时不可用、超时、服务器重启 → **自动重试**（最多 3 次，间隔递增），对用户仍显示待审核；仍失败则标为处理失败并在后台提示管理员，不向用户显示内部错误 |
| 待审核时删除 | 允许；取消后台任务，释放预留配额 |
| 上传中断 | 文件完整接收后才建立条目；中断时清理临时文件，不占配额 |
| 每日次数 | 按北京时间零点重置 |
| 旧格式（格式 3） | 未通过，原因“旧格式，请用 Windows 版或转换工具升级” |
| 未通过原因的写法 | 面向用户：指出哪本题库、哪道题、什么问题；不显示内部异常或堆栈 |
| 导入练习空间 | 只有“已审核 · 通过”的题库可以导入；待审核或未通过时按钮不可用 |
| 拓展审核状态变化 | 可用性在读取时由白名单推算：管理员之后批准拓展，相关条目自动变为通过；撤销拓展则相关条目变为不可用 |
| 后台队列管理 | 管理后台显示队列长度、正在处理的任务、处理失败的任务（可重试、查看原因） |
| 已有数据 | 变更前直接导入练习空间的私人题库，迁移时为其在“我的题库”中补建对应的私人题库包条目 |

### 6.0a 更正（2026-11-02，需求 FR-11 v1.15，优先于 6.0）

- “我的题库”的资源只有三类：**自己发布的公开题库包**（含审核状态）、**自己上传的私人题库包**（含审核状态）、**收藏的广场题库包**。从广场“加入”他人题库不再产生资源。
- 广场题库包详情与“我的题库”的收藏中提供：**下载到本地**（原始文件）、**导入练习空间**（按本选择，可多次，每次独立）。由广场导入的实例记录 `source_pack_id`、`source_bank_uuid`、`source_revision`，按第 3 节随作者更新；由私人资源导入的实例不更新。
- 第一版广场不设分类列表，发布时不填写分类（字段保留为空）。

### 6.0 “我的题库”与练习空间分离（2026-11-02，需求 FR-11 v1.14；与 6.1～6.5 冲突时以本节为准）

```text
我的题库（资源，用户级）                         练习空间（做题）
  私人上传的题库包（不公开）──┐
  发布到广场的题库包 ─────────┼─“导入练习空间”（按本选择，可多次）─► practice_collection 实例 → 作答、历史
  从广场加入的题库包 ─────────┘
```

- **资源**：每个资源是一个题库包（可含多本题库）。私人上传**重新引入“私人题库包”**：上传即创建一个不公开的包及其版本，保存**原始文件**（逐字节一致），解析与校验沿用现有导入代码；审核状态按 6.2。从广场加入的资源指向公开包（加入时选定的已审核版本，按第 3 节随作者更新）；收藏也显示在“我的题库”。
- **导入练习空间**：从资源中选择一本或多本，创建 `practice_collection` 实例（记录来源资源、包、版本与 `bank_uuid`）。同一资源可多次导入，每次独立。含未批准拓展的题库不能导入（6.2）。
- **相互独立**：删除资源不删除已导入的实例，实例继续可用（内容是共享且不可变的）；删除实例不影响资源。由广场加入的实例照常接收版本更新；由私人资源导入的实例不更新。
- **练习空间不再提供导入、导出**；“我的题库”提供上传、下载（返回原始文件）、删除资源、导入练习空间、发布到广场（私人资源直接用原文件发布，不重新打包）。
- **配额**：私人上传的内容按原始文件大小（或展开后大小，以实现说明为准）计入上传者配额；只要该资源或由它导入的任一实例仍存在就继续计入，两者都删除后释放。广场资源不计入。
- **UUID**：一个包内 UUID 唯一由格式保证；由于不再从练习空间分组打包导出，不会出现导出时 UUID 重复的问题。


### 6.1 私人导入与公开分享（2026-10-30 修订，需求 FR-11 v1.7）

**私人导入只是导入**：用户在练习空间上传 `.qbank`，平台解析、校验、存储内容（与题库广场共用同一条导入代码），为上传者创建题库实例。**不创建题库包、不填写广场信息**，`practice_collection.source_pack_id` 为 NULL，来源文件名记录在 `source` 中。每次导入都是独立实例（C-01），不参与自动更新。

**公开分享**有两个入口，结果相同：创建一个 `catalog_pack`（公开）及其第 1 个版本，填写标题、简介、截图、标签，提交人工审核。

| 入口 | 内容从哪里来 |
| --- | --- |
| 从本地上传 `.qbank` 到题库广场 | 走导入流程解析、存储（相同内容只存一份） |
| 从“我的题库”选择题库分享 | **直接复用**这些实例已引用的题库内容与拓展，不重新上传；只能选择 `source_pack_id` 为 NULL（自己上传）的实例，从题库广场加入的他人题库不能分享 |

分享后，上传者原有的私人实例保持不变，不自动关联到新的题库包。

### 6.2 审核与可用性

审核针对**拓展代码**：拓展的 JS 规则在服务器上执行，可能占用大量内存或死循环。

| 包内拓展的情况 | 结果 |
| --- | --- |
| 全部拓展摘要都在白名单中且状态为 `approved` | 上传后**立即可用** |
| 有拓展未审核 | 自动提交拓展审核；题库在“我的题库”中显示“审核中”，**不可打开** |
| 有拓展审核不通过 | 显示“未通过”及原因，用户可以删除 |
| 拓展被撤销审核（C-04） | 使用它的所有题库变为不可用，显示“拓展已停用” |

**可用性不存成题库实例上的字段，而是在读取时由白名单推算：**

```sql
-- 该题库内容用到的拓展中，是否存在未批准的
SELECT COUNT(*) FROM (SELECT DISTINCT extension_digest FROM content_question WHERE bank_id = ?) q
LEFT JOIN admin_extension_review r ON r.digest = q.extension_digest AND r.status = 'approved'
WHERE r.digest IS NULL;
```

原因：审核按拓展摘要记录，一次审核会同时影响很多用户的很多题库。如果把状态复制到每个题库实例上，审核通过或撤销时就要批量修改所有相关的行，容易遗漏、产生不一致；推算的方式在审核状态变化后**下一个请求就生效**。题库内容不可变，“某本题库用到哪些拓展”的结果可以缓存，只有白名单查询需要实时进行。

**审核不代替隔离：** 已审核的拓展照样在 rule-runner 的隔离环境中执行，受内存和时间限制（ADR-003、rule-runner 协议第 7 节）。审核是第二道防线。

### 6.3 “我的题库”的三种来源

| 来源 | 数据 | 说明 |
| --- | --- | --- |
| 从题库广场加入 | `practice_collection`，`source_pack_id` 指向公开包 | 自动更新（第 3 节） |
| 自己上传（私人导入） | `practice_collection`，`source_pack_id` 为 NULL | 可用性见 6.2；不参与自动更新 |
| 收藏 | `catalog_favorite(user_id, pack_id, created_at)` | 只是书签，不是题库实例；点击后选择加入哪几本 |

### 6.4 下载与导出

- **题库广场下载**：返回该版本的 `.qbank` 文件（`catalog_pack_revision` 记录其 `blob_sha256`），由 Nginx `X-Accel-Redirect` 发送，必须逐字节一致：Windows 客户端会校验 `sha256`（C-05）。从本地上传的版本保存作者上传的原文件；从“我的题库”分享的版本在发布时由已存储内容打包一次并保存，之后每次下载都返回这一份。
- **导出我的题库**：从共享内容重新打包，不含作答、草稿和历史。

### 6.6 实现说明（题库广场 1/4，2026-11-02）

- **发布入口**：本 PR 只提供从本地上传 `.qbank` 发布（保存作者上传的原文件，逐字节一致）。从私人题库包（6.0 的“我的题库”资源）发布在下一个 PR 中实现，同样直接使用原文件，不重新打包。
- **广场信息按版本保存**：标题、简介、详细说明、分类、标签、截图、更新说明都是 `catalog_pack_revision` / `catalog_pack_file` 的列，`catalog_pack` 只保留所有者、`latest_revision`、`approved_revision` 与状态。新版本审核期间，广场继续显示上一个已审核版本的信息与内容；管理员审核的是这一版的全部内容。
- **版本的审核状态**：`pending` 待审核、`approved` 已通过、`rejected` 未通过（不能重新提交，须发布新版本）、`superseded` 待审核期间发布者又上传了新版本（旧的不再审核）、`withdrawn` 发布者删除了整个包。
- **题库身份**：`content_bank.bank_uuid`（V21）记录 bank.json 的 UUID；私人导入的实例同样写入 `practice_collection.source_bank_uuid`。
- **发布者操作的记录**：发布、上传新版本、删除，以及审核结果，按题库包写入 `catalog_pack_event`（只插入）；管理员操作另写 `admin_audit`。
- **加入我的题库**：`POST /api/catalog/packs/{id}/practice` 的最小实现（从已审核版本按本加入、重复加入打开已有实例、删除或未审核的包不能加入），供本 PR 的测试使用；按 6.0 改为“加入我的题库资源 + 导入练习空间”在下一个 PR 中完成。

## 7. 测试要点

1. 没有作答的用户打开题库：直接是新版本。
2. 有作答（草稿、已提交或已完成本轮）的用户：继续使用当前版本，看到提示；点“再练一次”后作答清空并切换到新版本。
3. 作者删除题库包：用户的题库仍能正常练习，显示“作者已移除”。
4. 并发：同一用户两个页面同时打开题库，只切换一次；切换与第一次保存并发时，不会出现旧版本题目的作答写入新版本。
5. 新版本审核期间，用户和广场看到的都是上一个已审核版本。
6. 审核通过后生成一条题库更新通知，只对拥有该题库的用户可见。
