# 题库共享与版本更新

> **文档版本：** v0.2
> **日期：** 2026-10-28
> **依据：** [需求 FR-10、FR-11](../requirements/01-requirements.md)，[数据库设计](01-database.md)，[rule-runner 协议](03-rule-runner-protocol.md)

本文说明三件事：题库内容如何在用户之间共享；作者增、删、改题库后，用户的题库如何变化；自动更新的具体算法与并发处理。

---

## 1. 概念回顾

```text
题库包（catalog_pack）            作者上传的一个“组”，包含多本题库
 └─ 版本（catalog_pack_revision）  作者每次更新产生一个新版本，需审核
     └─ 包内题库（catalog_pack_bank） 某版本中的一本题库 → 指向一份共享内容（content_bank）

用户的题库实例（practice_collection）  指向某个包内题库的某个版本的内容
 └─ 作答、草稿、历史、考试             用户私有
```

- **共享内容不可变**：每个版本的每本题库对应一份 `content_bank`；内容相同则复用同一份（`content_sha256` 唯一）。
- **包内题库的身份（2026-10-29 修订）**：`bank_uuid` = `bank.json` 中必填的 UUID（设计 06 第 4 节）。新旧版本中 UUID 相同的题库视为“同一本题库的不同版本”，作者修改文件夹名不影响对应关系。下文及第 4 节中的 `bank_key` 一律改为 `bank_uuid CHAR(36)`。

## 2. 作者操作与用户效果

| 作者操作 | 平台处理 | 已加入的用户 |
| --- | --- | --- |
| **增**：上传新的题库包 | 新建 `catalog_pack` 与第 1 个版本，审核通过后公开 | 无影响 |
| **改**：上传新版本 | 新建版本，审核中时**继续公开上一个已审核版本** | 新版本审核通过后自动更新（第 3 节） |
| 新版本中去掉某本题库 | 该 `bank_key` 在新版本中不存在 | 保留该题库，停在最后一个版本，标记“作者已移除，不再更新” |
| 新版本中题库改名 | 视为删除旧题库 + 新增一本 | 旧题库同上保留；新题库需要用户自己加入 |
| **删**：删除整个题库包 | 题库包下架，不再出现在广场中 | 全部保留，标记“作者已移除，不再更新” |
| **查**：查看题库包信息 | 只读 | 无影响 |

> 与旧 Hub 的差异：旧 Hub 中作者编辑后，整个题库包暂停公开，直到重新审核通过。V2 改为新版本审核期间继续提供上一个已审核版本，用户不会因为作者正在修改而看不到题库。

**共享内容不会因作者删除而丢失：** 内容只有在**没有任何用户实例、历史记录、考试和题库包版本引用**时，才会被后台垃圾回收删除（ADR-007）。

## 3. 自动更新规则（2026-10-29 简化）

**原则：只在一本题库“没有进行中的作答”时切换版本，切换时整本替换，不做逐题合并。** 作答与题目永远来自同一个版本，不会出现“新题配旧作答”。代价是用户正在做的这一轮，要等到下一轮才用上新版本；题库更新不频繁，这个代价可以接受（需求 FR-10 v1.6）。

### 3.1 何时切换

“有进行中的作答”指：该题库的普通练习存档中存在状态为 `draft` 或 `submitted` 的作答行，或者该题库有进行中 / 评分中的考试。

| 用户题库的状态 | 处理 |
| --- | --- |
| 没有进行中的作答（从没开始，或“再练一次”后尚未作答） | 下次打开时**直接切换**到最新的已审核版本 |
| 有进行中的作答（含已点“完成”、但还没点“再练一次”） | **不切换**，继续使用当前版本；概览中提示“有新版本，再练一次时使用” |
| 用户点击“再练一次” | 在同一个事务中：清空作答（与原有“再练一次”相同）→ 切换到最新的已审核版本 |

不提供“立即更新”。考试引用开考时的 `bank_id`，本身就是冻结的；新开的考试使用题库实例当前的版本。

### 3.2 何时检查

**懒更新：不在作者发布时批量修改所有用户的数据，而是在用户打开题库时检查。**

- 用户请求题库概览（`GET /api/collections/bank/{id}`）或“再练一次”时，比较 `practice_collection.source_revision` 与该题库包最新的**已审核**版本。
- 可以切换 → 在本次请求中完成切换，再返回新版本的概览。
- 暂不能切换 → 返回当前版本概览，附带 `update:{status:"pending", revision}`。

为什么不在发布时批量更新：

1. 批量修改几百个用户的数据是一个耗时的大事务，容易和用户正在进行的保存冲突；
2. 很多用户可能很久都不会再打开这本题库，提前更新没有意义；
3. 懒更新让每个用户的切换都是一个独立的小事务，失败只影响这一个人，下次打开时重试即可。

### 3.3 通知

版本审核通过时，系统自动发送一条题库更新通知（需求 FR-12，`notification.kind = 'bank_update'`，`pack_id` 关联该题库包），内容包含作者填写的更新说明。拥有该题库的用户在通知列表中看到它，不为每个用户复制。

### 3.4 事务与并发

切换只修改题库实例指向的内容，不碰作答行（切换时本来就没有进行中的作答）：

```text
BEGIN
  SELECT ... FROM practice_collection WHERE id = ? AND user_id = ? FOR UPDATE
      —— 锁住题库实例：防止同一用户两个页面同时触发切换
  再次确认：source_revision 仍是旧值（已被另一个请求切换则直接结束）
  SELECT ... FROM practice_context WHERE collection_id = ? AND kind = 'practice' FOR UPDATE
      —— 锁住普通练习存档：与保存、提交、完成本轮互斥（加锁顺序：collection → context → state）
  再次确认没有进行中的作答（第 3.1 节的条件），否则结束
  practice_collection.bank_id = 新内容，source_revision = 新版本，update_status = 'current'
  practice_context.progress_version + 1
COMMIT
```

- 切换不需要调用 rule-runner：新版本每题的满分已在导入时算好。
- 切换与第一次保存并发时：两者都要锁住普通练习存档，后者等待前者提交后再执行；如果切换先完成，前端拿着旧版本读到的题目保存，会因题目内容版本不一致被拒绝并刷新。
- 冻结历史永不改变：`practice_round` 与 `practice_round_question` 保存当时的快照，并引用当时的拓展包摘要。
- 分组名、用户自定义的标题保留，不被作者的新标题覆盖。

## 4. 数据库变更

```sql
CREATE TABLE catalog_pack_bank (                   -- 某个版本中的一本题库
  pack_id    CHAR(36)      NOT NULL,
  revision   INT           NOT NULL,
  bank_uuid  CHAR(36)      NOT NULL,               -- bank.json 中的 UUID：题库身份（设计 06 第 4 节）
  bank_id    CHAR(36)      NOT NULL,               -- 共享内容 content_bank.id
  title      VARCHAR(300)  NOT NULL,
  PRIMARY KEY (pack_id, revision, bank_uuid),
  KEY idx_pack_bank_content (bank_id)
);
```

`practice_collection` 的来源与更新状态字段（V1 中的 `source_bank_key` 在实现题库广场时改为 `source_bank_uuid CHAR(36)`）：

```sql
  source_pack_id    CHAR(36)  NULL,                -- 指向公开包或私人包（第 6 节）
  source_bank_uuid  CHAR(36)  NULL,
  source_revision   INT       NULL,                -- 当前使用的版本
  update_status     ENUM('current','pending','removed') NOT NULL DEFAULT 'current',
      -- pending：有新版本，等待没有进行中的作答时切换；removed：作者已移除，不再更新
  KEY idx_collection_source (source_pack_id, source_bank_uuid)
```

`catalog_pack` 增加 `approved_revision`（最新的已审核版本），审核通过时更新；用户打开题库时与 `source_revision` 比较。

## 5. 接口变更

| 接口 | 变更 |
| --- | --- |
| `GET /api/collections/bank/{id}` | 响应增加 `update:{status, revision?, removed?}`；可以切换时，在返回前完成切换 |
| `POST .../restart`（再练一次） | 若有更新的已审核版本，清空作答后切换到新版本 |
| `POST /api/packs/{id}/practice` | 加入“我的题库” `{banks:[bank_uuid…]}`，按本选择；同一用户重复加入同一本时，打开已有的实例 |

## 6. 我的题库与私人题库（需求 FR-11）

### 6.1 私人导入与公开分享（2026-10-30 修订，需求 FR-11 v1.7）

**私人导入只是导入**：用户在练习空间上传 `.qbank`，平台解析、校验、存储内容（与题库广场共用同一条导入代码），为上传者创建题库实例。**不创建题库包、不填写广场信息**，`practice_collection.source_pack_id` 为 NULL，来源文件名记录在 `source` 中。每次导入都是独立实例（C-01），不参与自动更新。

**公开分享**有两个入口，结果相同：创建一个 `catalog_pack`（公开）及其第 1 个版本，填写标题、简介、截图、标签，提交人工审核。

| 入口 | 内容从哪里来 |
| --- | --- |
| 从本地上传 `.qbank` 到题库广场 | 走导入流程解析、存储（相同内容只存一份） |
| 从“我的题库”选择题库分享 | **直接复用**这些实例已引用的题库内容与拓展，不重新上传；只能选择 `source_pack_id` 为 NULL（自己上传）的实例，从题库广场加入的他人题库不能分享 |

分享后，上传者原有的私人实例保持不变，不自动关联到新的题库包。

### 6.2 审核与可用性

审核针对**拓展代码**：拓展的 JS 规则在服务器上执行，可能占用大量内存或死循环。

| 包内拓展的情况 | 结果 |
| --- | --- |
| 全部拓展摘要都在白名单中且状态为 `approved` | 上传后**立即可用** |
| 有拓展未审核 | 自动提交拓展审核；题库在“我的题库”中显示“审核中”，**不可打开** |
| 有拓展审核不通过 | 显示“未通过”及原因，用户可以删除 |
| 拓展被撤销审核（C-04） | 使用它的所有题库变为不可用，显示“拓展已停用” |

**可用性不存成题库实例上的字段，而是在读取时由白名单推算：**

```sql
-- 该题库内容用到的拓展中，是否存在未批准的
SELECT COUNT(*) FROM (SELECT DISTINCT extension_digest FROM content_question WHERE bank_id = ?) q
LEFT JOIN admin_extension_review r ON r.digest = q.extension_digest AND r.status = 'approved'
WHERE r.digest IS NULL;
```

原因：审核按拓展摘要记录，一次审核会同时影响很多用户的很多题库。如果把状态复制到每个题库实例上，审核通过或撤销时就要批量修改所有相关的行，容易遗漏、产生不一致；推算的方式在审核状态变化后**下一个请求就生效**。题库内容不可变，“某本题库用到哪些拓展”的结果可以缓存，只有白名单查询需要实时进行。

**审核不代替隔离：** 已审核的拓展照样在 rule-runner 的隔离环境中执行，受内存和时间限制（ADR-003、rule-runner 协议第 7 节）。审核是第二道防线。

### 6.3 “我的题库”的三种来源

| 来源 | 数据 | 说明 |
| --- | --- | --- |
| 从题库广场加入 | `practice_collection`，`source_pack_id` 指向公开包 | 自动更新（第 3 节） |
| 自己上传（私人导入） | `practice_collection`，`source_pack_id` 为 NULL | 可用性见 6.2；不参与自动更新 |
| 收藏 | `catalog_favorite(user_id, pack_id, created_at)` | 只是书签，不是题库实例；点击后选择加入哪几本 |

### 6.4 下载与导出

- **题库广场下载**：返回该版本的 `.qbank` 文件（`catalog_pack_revision` 记录其 `blob_sha256`），由 Nginx `X-Accel-Redirect` 发送，必须逐字节一致：Windows 客户端会校验 `sha256`（C-05）。从本地上传的版本保存作者上传的原文件；从“我的题库”分享的版本在发布时由已存储内容打包一次并保存，之后每次下载都返回这一份。
- **导出我的题库**：从共享内容重新打包，不含作答、草稿和历史。

### 6.5 数据库变更

```sql
-- catalog_pack 增加（题库包只用于公开分享；私人导入不创建题库包，需求 FR-11 v1.7）
  owner_id    CHAR(36) NOT NULL,                   -- 发布者

CREATE TABLE catalog_favorite (
  user_id     CHAR(36)     NOT NULL,
  pack_id     CHAR(36)     NOT NULL,
  created_at  DATETIME(3)  NOT NULL,
  PRIMARY KEY (user_id, pack_id)
);
```

`practice_collection.source_pack_id` 只对从题库广场加入的实例填写；私人导入为 NULL（2026-10-30 修订）。

## 7. 测试要点

1. 没有作答的用户打开题库：直接是新版本。
2. 有作答（草稿、已提交或已完成本轮）的用户：继续使用当前版本，看到提示；点“再练一次”后作答清空并切换到新版本。
3. 作者删除题库包：用户的题库仍能正常练习，显示“作者已移除”。
4. 并发：同一用户两个页面同时打开题库，只切换一次；切换与第一次保存并发时，不会出现旧版本题目的作答写入新版本。
5. 新版本审核期间，用户和广场看到的都是上一个已审核版本。
6. 审核通过后生成一条题库更新通知，只对拥有该题库的用户可见。
