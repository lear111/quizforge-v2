# L1.3 / L1.4 实施与验收计划

依据：02-practice-acceptance.md 及作者确认的性能约束。

- 完成练习：持久化任务、HTTP 202 + 进度查询；开始即锁作答/重做，失败恢复编辑，保留已完成的单题结果与其余草稿。pending/null 不阻止完成，汇总按 0 计，之后仍可人工改分。
- 每 app 只有一个后台工作线程，runner 请求标记 background；Java 端限制后台并发为 1 并保留前台名额。判分不持有数据库事务，任务可租约恢复。
- 单题保存/提交仍按乐观锁与原回执重查；增加上下文的共享状态锁，允许不同题草稿并发，与完成/再练的排他状态转换互斥。
- 提交不再构造题库或历史快照；轮次只保留轻量身份。只有再练请求启动历史构建，完成后同事务发布历史并重置作答/白板；构建期间冻结当前轮次，幂等请求不重复构建。
- 历史包含所有题的投影、状态、最后一次作答、评分、两层白板、题序与大纲、拓展摘要与格式版本，不包含原始答案数据。记录尝试次数、首次对错、评分来源。
- 历史列表 SQL 只选摘要，详情才读快照和固定拓展页面；追加笔记复用白板校验，既有笔迹不可改；删除与题库连带删除覆盖历史批注和资源授权引用。
- 高频路径只查当前 context/题目/白板，不枚举全库。保留 L1.5 的草稿锁定判断，不计练习配额。

验收：真实 MySQL + runner，成功/失败/权限/重放/并发/重启租约/完整历史/旧版本兼容/资源权限，前端与浏览器测试，300 题背景批量任务期间与无任务的单题提交 P95 对照（相同环境、预热、样本数与错误率一并报告）。最终 CI 四项通过，PR 不合并，独立 Compose down、工作目录 detach。
