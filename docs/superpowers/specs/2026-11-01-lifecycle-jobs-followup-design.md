# 后台练习任务后续改进设计

## 范围

只实现任务中的 PR 1，分支 `fix/lifecycle-jobs-followup`，起于 main `bf9f6c7`，实施期间同步 main `c43eaed`，随后按补充要求 merge main `c0d0030`。PR 2 的小题草稿状态必须等 PR 1 由作者审查合并后再开始。不修改判分、草稿、白板、幂等回执和租约围栏的语义。

## 实施方案与取舍

保留现有单工作线程，改为一次只安排一个后续任务的可唤醒调度器。相较新增常驻线程配合条件变量，这样可以直接沿用 ScheduledExecutorService，并用可控调度器测试时间与并发；不引入依赖。作者已明确选择按原任务直接实施、跳过额外设计流程。

领取查询建议使用持久化生成列 `available_at` 和 `(available_at, id)` 索引。排队任务取 updated_at，运行中任务取 lease_until，已结束任务取 NULL；范围查询直接排除已结束任务。相较拆成两条 queued/running 领取 SQL，这样仍只有一次加锁查询，并可统一安排排队与过期租约。按可领取时间、id 排序；保留运行中租约必须严格过期的判断。

## 调度与唤醒

- 有任务保持默认 250ms 节奏，沿用现有可配置 interval。
- 连续没有任务时，间隔逐步加倍，到 5 秒封顶；找到任务或新建任务后重置。
- finish/restart 新任务只在事务提交成功后唤醒本实例；回滚不唤醒。若工作线程正在执行，记录唤醒请求，下一次立即调度；不得并发执行两个 tick。
- 对已取消的定时回调使用调度代次校验，避免取消与开始执行的竞态造成重复调度。关闭后不再唤醒。
- 其他实例创建的任务最多等待本实例 5 秒发现，不增加跨实例通知系统。

## 清理

- 默认保留 completed/failed 7 天，保留时长可配置；以结束时更新的 updated_at 判断。
- 建议每小时执行清理，每种终态每次最多删除 200 行；单条 DELETE 自身提交，不把多批合进大事务，不在一个 tick 中追删到空。
- 新增 `(status, updated_at, id)` 索引，按确定顺序删除；SQL 同时限制终态，不能删除 queued/running。
- 任务过期后原 jobId 查询返回现有 NOT_FOUND；练习状态、历史和幂等回执不随任务表清理删除。原 requestId 的回执仍保留原 jobId，不重新执行旧任务。

## 归档游标与迁移

- 新增 V14 迁移，不修改已应用迁移（main V12 为管理审计、V13 为通知中心）。归档任务保存可空的最后已处理 position。
- 查询 `bank_id = ? AND position > ? ORDER BY position LIMIT 1`；首次不加 position 下界，支持不连续以及非零起始值。
- 快照写入、completed 增加和游标更新在同一事务内。失败、进程重启和租约接管后从已提交游标继续，不能因心跳而提前推进。
- 升级时对已有执行中的归档任务，从该轮已冻结题目恢复最大 position；完成题数仍保留原值。

## 测试与证据

- 可控调度器逐次触发，验证退避上限、找到任务恢复 250ms、提交后立即唤醒、执行期间唤醒、取消竞态和停止；不使用固定 sleep。
- Testcontainers MySQL：只清理严格过期终态、边界保留、每批上限、活动任务保留；真实 SQL 验证键集顺序与游标提交、租约恢复。
- 新迁移升级测试覆盖已处理一部分的旧归档任务。
- 在包含大量已结束任务与少量可领取任务的独立 MySQL 中记录旧/新 EXPLAIN、索引和排序证据；只报告实测结果。
- 回归现有完成/历史、草稿/提交测试；完整验证交 CI 四项。
- 现有 CI 只对 PR 与 main 推送运行。为满足“先 CI 全绿再开非草稿 PR”，优先增加手动触发入口，在分支上运行同一个 CI；若平台不允许该入口在合并前触发，明确报告并由作者决定流程，不先开草稿 PR 绕过。
