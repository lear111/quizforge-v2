# 架构决策记录（ADR）

ADR 记录一项重要架构决策：当时面对什么问题、考虑过哪些方案、选了哪个、为什么，以及要承担什么后果。目的是让以后的人（包括面试官和半年后的自己）能看懂“为什么这样设计”，而不只是“设计成了什么样”。

## 规则

- 每个 ADR 一个文件，命名为 `ADR-编号-简短英文名.md`，编号不复用。
- 状态取值：**提议** → **已接受** / **已否决**；被新决策取代时改为 **已取代（见 ADR-xxx）**，原文保留不删。
- 已接受的 ADR 不再修改正文；要改变决策，就新写一个 ADR 取代它。
- 每个 ADR 都要写明“如何验证”，即用什么测试或指标证明这个决策是对的。

```markdown
## 背景
## 决策驱动因素
## 备选方案
## 决策
## 后果
## 如何验证
```
