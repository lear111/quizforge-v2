# ADR-011：判分与规则计算尽量在浏览器中执行

- 状态：已接受（作者 2026-11-02 决定）
- 日期：2026-11-02
- 相关需求：FR-03、FR-08、FR-11、FR-14
- 相关决策：[ADR-003](ADR-003-extension-rule-execution.md)（服务器端规则执行）、[ADR-006](ADR-006-frontend-reuse.md)（复用旧前端）

## 背景

拓展规则（`validateBank`、`project`、`grade`、`scoreBatch` 等）是 JS 代码，服务器在 rule-runner 的隔离 Node 进程中执行。它是服务器上最贵的部分：每次调用都要进程间通信和新的隔离环境，拓展种类多于进程上限时还会反复重启进程。本机实测：导入一个使用 8 种拓展、包内题库较多的真实题库包（几 MB），逐本校验总计超过 60 秒。

拓展页面本来就在用户浏览器中运行（渲染题目、收集作答）。下载的题库包包含完整答案（FR-11：可下载的题库不承诺答案保密）。

## 决策驱动因素

1. **服务器主要负责数据库读写**；判分这类纯计算尽量交给用户的浏览器，减轻服务器负担（作者决定）。
2. **分数是否可被用户篡改不重要**：练习分数只影响用户自己（作者决定）。
3. 仍然要保证“提交前在线拿不到答案”这一练习体验：**先锁定作答，再给出答案与解析**。
4. 没有浏览器在场时（关闭页面后到期自动交卷、完成练习时页面已关闭、管理员审核、发布）仍需服务器能完成。

## 决策

**默认在浏览器中执行规则，服务器只在没有浏览器或必须由服务器保证结果的场景执行。**

| 场景 | 由谁执行 | 说明 |
| --- | --- | --- |
| 练习中单题提交 | **浏览器** | 服务器先锁定作答（状态：已提交、待判分），再返回提交后数据（含答案、解析）；拓展在浏览器中 `grade`，把结果上报，服务器记录评分来源 `browser` |
| 完成练习 / 考试交卷（页面打开时） | **浏览器** | 页面逐题本地判分并上报；全部上报后完成 |
| 页面关闭后到期自动交卷、上报中断 | 服务器兜底 | 浏览器下次打开时可以先补判；超过时限仍未上报的由服务器后台判分（低优先级、限速） |
| 私人上传题库 | ~~浏览器优先~~ **服务器后台排队**（2026-11-02 修订，见设计 04 第 6.0b 节） | 浏览器在上传前本地执行 `validateBank` / 大纲 / 满分计算，与文件一起提交；服务器只做结构与安全校验（解压规则、大小、文件头、白名单），不再逐本运行规则 |
| 发布到广场、管理员审核 | 服务器 | 内容会给其他用户使用，满分与大纲以服务器计算为准；放在后台任务中执行，显示进度 |
| 读题的投影（`project`） | 维持现状（服务器 + 缓存） | 投影已按题缓存；提交后的投影通常与作答无关，可按题共享 |
| AI 判分、AI 辅导 | 服务器 | 需要服务器调用模型并扣费 |
| 组织考试（FR-13） | 服务器 | 成绩需要可信 |

补充规则：

- **原始数据的返回边界（需求 FR-11 v1.17）**：作答被服务器锁定为已提交之后，才向作答者本人返回这道题的原始数据（供浏览器中的规则 `grade` / `project` 使用）；提交前、其他题目、其他用户一律不返回。
- **浏览器中的规则执行环境**：只执行已批准的拓展；在独立的沙箱环境（Web Worker 或沙箱 iframe）中运行，不能访问宿主页面的 Cookie、存储与网络，有时间上限，超时视为判分失败并交给服务器兜底。

- 浏览器上报的分数仍按宿主的规则校验格式（分值在 0 与满分之间、小题 ID 属于本题），不校验正确性。
- 同一作答只接受一次判分结果（按提交版本 / generation 条件更新），重复上报幂等。
- 人工改分、AI 评分照常覆盖（FR-14，以最后一次为准）。
- 服务器端 rule-runner 保留，用于兜底与上表中的服务器场景；规模可以相应减小。

## 后果

- 服务器的规则计算主要剩下：发布与审核、兜底判分、投影缓存未命中。练习高峰时服务器只做数据库读写。
- 练习分数由浏览器决定，技术用户可以篡改自己的分数；历史、AI 分析与统计中的练习分数不作为可信数据使用。
- 提交流程从“一次请求完成”变为“锁定 → 取答案 → 本地判分 → 上报”，需要处理中途关闭页面与重复上报。
- 前端分叉中拓展已在 iframe 中运行；需要让拓展在浏览器中可调用 `grade` 等规则（SDK 提供本地规则执行，仍在沙箱 iframe 中，不能访问宿主 Cookie）。
- 浏览器端与服务器端执行同一份拓展代码，结果应一致；服务器兜底时同样记录评分来源。

## 如何验证

- 练习单题提交、完成练习、考试交卷在页面打开时不调用 rule-runner（集成测试断言调用次数为 0）。
- 关闭页面后到期交卷、上报中断能由服务器兜底完成。
- 上传请求只保存文件、立即返回；校验在后台队列中完成，不影响练习请求的 P95。
- 先锁定后取答案：未提交时任何接口都拿不到答案（沿用现有安全测试）。
